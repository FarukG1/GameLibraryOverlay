# Updater design

[Documentation index](README.md)

The current application has no updater. Adding one changes application behavior
and should be implemented as a separate feature.

## Recommended approach

[Velopack's WPF integration](https://docs.velopack.io/getting-started/wpf) provides
installation, update downloads, and application restart. It requires application
startup integration and a packaging step; attaching the current portable ZIP to
GitHub Releases alone does not provide automatic updates.

An implementation would:

1. Add the Velopack dependency and initialize its startup hooks before normal app
   startup, including single-instance handling.
2. Package each Windows architecture separately with `vpk`, using the central
   version from `Directory.Build.props`.
3. Configure the actual public GitHub repository as the update source, and publish
   the installer, update packages, and release feed generated by the packager.
4. Add a tray or Settings action to check for updates and show release notes.
5. Download an accepted update, then ask to restart when no tracked game session
   is active. Persist settings before restart and release single-instance handles.
6. Preserve `%LOCALAPPDATA%\GameLibrary` across upgrades and test startup
   registration, locked files, network failures, and interrupted downloads.

Start with explicit user-triggered checks. If background checks are added later,
make their behavior configurable and document the new network activity.
Sign Windows installers and executables for a public distribution, and validate
update integrity through the framework's supported mechanisms. Test upgrades
between two packaged versions, including launch failures and settings recovery.

See [packaging](https://docs.velopack.io/packaging/overview) and
[update integration](https://docs.velopack.io/integrating/overview) for the release
assets and download/apply lifecycle. Keep the portable ZIP as an optional separate
distribution; do not promise installer updates for portable copies without
implementing and testing that path.
